Learning About Levels

October 20th, 2020

One of my modules this year is Game Level Design. I'll be learning about the fundamentals of level design and will be creating a level throughout the year using Unreal Engine (my first time using it). To get a grasp of everything that level design entails, I began researching similarities between job listings for level design roles. Here were some of the key points:

- Working alongside gameplay programmers to develop levels based off of key gameplay mechanics
- The ability to tell stories and support narrative through environmental storytelling
- The ability to analyse game worlds/levels and understand what makes them fun
- Experience crafting levels or worlds with modern level building software (UE4, Unity, CryEngine, etc)
- Developing basic underlying principles of the game (game mechanics, levels, etc.).
- Expertise in programming, art, or architecture is greatly valued

I have a little prior experience in designing levels, though not published. A while ago, I decided to make a map for Counter-Strike: Global Offensive using their SDK, though when university continued, I put the project aside until I found more time to work on it.



This taught me a lot about levels. As Counter-Strike is a strategic, teamwork-based multiplayer shooter, designing the level became about balancing it for both teams above all else: Providing cover, chokepoints, retake opportunities and sightlines, all while making the map unique compared to other maps in the game became a juggling act, and I soon realised how much effort is put into professional level design, with even just blocking out the map taking days upon days.

So now I know some bits and bobs about what's involved in level design, I'm looking forward to working on my project over the next few months. While I am a big fan of gameplay programming, I've now realised that the two roles are intertwined and must take advantage of each other to succeed. This can be seen in all sorts of games, from my example of CS:GO, to platformers like Celeste, and puzzlers like Snake Pass. Let's see where this journey through level design takes me...

Blocky Beginnings

October 19th, 2020

Today, I'm starting my first course project of the year - For my Game Engine Architecture module, I've been tasked to recreate a game mechanic from a particular game in two separate engines. Given the choice between Portals (from Portal), Blocky (Minecraft's terrain generation), Marionette (a physics-based ragdoll system), and Sketch (stylistic rendering system), I chose to pick Blocky.



This involves procedural generation of blocky terrain and voxel mesh optimisation.
Some of the features I want to include in this are:
- Generation of surface terrain using 2D Noise
- Voxel mesh optimisation to allow it to run smoothly
- Generation of cave systems using 3D Noise or otherwise
- Inclusion of biomes, where certain areas will have different terrain features
- Ability to manually edit terrain without performance losses due to mesh generation

I will be attempting to create these mechanics in two engines, being Unity (as I have experience using it) and Godot (as I would like to learn how to use it in the process.)

To kick things off, I opened Unity and got to work on generating the surface terrain, the first feature of my list.
That's the end of this blog post for now, so I'll get back to you later on how it goes...
